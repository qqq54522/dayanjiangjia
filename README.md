# 洋葱学园直播工作台 · 本地协作版

工具代码共享在 [GitHub 仓库](https://github.com/qqq54522/dayanjiangjia)。每人运行自己的工作台，使用自己的 Codex 改稿和开发功能。文稿和图片保存在本机，通过内部飞书传送文稿包；不存入代码仓库。

## 第一次使用

需要 Git。公开仓库可直接克隆；若仓库将来改为私密，需先获得访问权限并在自己的电脑配置 GitHub 身份。首次安装推荐运行：Mac 双击 `安装工作台.command`，Windows 双击 `安装工作台.cmd`。安装入口会检测 Node.js 24、LibreOffice、Poppler、FFmpeg；缺失时通过 Homebrew 或 WinGet 安装，系统可能要求管理员确认和联网。已有工具会复用。Mac 尚未安装 Homebrew 时会运行其官方安装程序；Windows 缺少 WinGet 时需先安装 Microsoft App Installer。

如果已经有 Node.js 24 或更新版本，也可以让自己的 Codex 阅读 [AGENTS.md](AGENTS.md)，执行：

```sh
npm run setup
npm start
```

打开 http://127.0.0.1:8788 。Mac 日常使用可双击 `启动工作台.command`。无需 Pages、Cloudflare 或他人的 ChatGPT 账号；使用第三方 Codex 服务时，可在项目广场或编辑页顶部「设置」选择工作台专用连接，填写该电脑的服务 URL、模型 ID 和 API Key，保存后点击「测试 / 重新连接」。该测试由本机 Codex CLI 发起真实最小请求，不使用演示稿；仅看到「已登录」不代表模型连接成功。密钥仅存本机 `.local/cli-connection.json`，不会在设置页回显或进入 Git。第三方网关须支持 Codex 的 Responses API；若已有完整的本机 Codex 配置，也可直接沿用。首次安装需要联网下载依赖；工作台绑定本机，安装后可离线编辑。运行 `npm run doctor` 可查看每个转换工具的实际路径，`npm run setup:native` 可重新检测并补装缺失工具。

## 日常使用

- 打开后先进入项目广场，可新建项目或打开历史项目。旧版单项目草稿会自动进入历史项目。
- 在项目内编辑文字，上传图片/GIF/MP4；多选图片会进入同页轮播区。点击展示区放大，Esc 关闭。页面修改会自动保存到本机；返回广场前也会完成保存。
- 点击“交给 Codex”，工作台自动调用本机 Codex CLI，完成后在网页预览建议并应用。默认跟随各自本机的服务商、模型和凭证，也可调整并保存模型。复杂素材修改仍可在本机 Codex 对话中处理。
- 生成固定播出版本后，后续改稿不会改变它。工作台中的预演只在本机访问；通过「发布」生成的内网链接可在获准访问内网的设备上播放。
- 顶部「发布」可把当前草稿生成独立播放网页，上传到已配置的内网静态站，得到手机、iPad、电脑可打开的 HTTPS 链接。发布是手动操作，每次得到新链接；历史链接会在「发布」弹窗保留。播放页不含讲述提示和内部反馈。链接的可访问范围及保留时间由内网存储服务决定。

发布配置和接口见 [内网发布说明](docs/内网发布.md)。公司统一网关可由已配置的负责人导出一份 `company-publish-config.json`，通过内部渠道交给同事；同事把它放在项目根目录，首次安装时会自动导入本机 `.local/` 并移除根目录临时副本。这个文件包含共用 API Key，不能提交到仓库或发到公开链接。
- 文稿尚未做长期效果或营销事实核验，工具不会自动给出提分承诺。

## 与同事交换文稿

版本 → **导出 ZIP 文稿包（含全部素材）** → 得到一个 `.deck.zip` 文件 → 通过内部飞书手动发送 → 对方在版本里**导入文稿包**并保存。无须额外发素材文件夹。包中包含页面、图片/GIF/MP4、字体、讲述提示、反馈及固定版本。

不设置视频和文稿包的产品级文件大小限制；实际仍受设备内存、浏览器和 ZIP 格式能力限制。便携包只支持已上传到本机的素材；外部素材请先下载、上传。只接受 .deck.zip，不兼容旧 JSON 导入；本机已有文稿不受影响，可直接导出 ZIP。导出的独立 HTML 用于播放，不可代替可编辑文稿包。

一个工作台可保存多个独立项目。浏览器关闭后项目仍在 `.local/workspace.sqlite`，每次写入前按项目备份到 `.local/backups/`。图片在 `.local/media/`。不要删除 `.local/`，不要在两台电脑之间直接同步正在使用的数据库。与同事交换文稿仍使用 `.deck.zip`。

## 同步工具功能

项目广场和编辑页都有「更新工具」按钮。点击一次会检查 GitHub 的 `main`；有新版就自动拉取、安装、构建、重启并刷新页面。从 GitHub 克隆的新副本和原先从公司 GitLab 克隆的旧副本都能以 GitHub 为更新来源。更新不操作 `.local/` 中的文稿、图片和发布配置。代码目录必须处于干净的 `main` 分支；其他分支、未提交改动或需要处理的分叉都会停止更新并说明原因。命令行也可运行 `npm run update`，完成后手动重启工作台。

修改功能请让 Codex 建立 `codex/功能名` 分支，完成检查后运行：

```sh
npm run share-code -- "新增功能的简短说明"
```

脚本只暂存允许的代码路径、检查误入素材/凭证，提交后验证并默认合并 main，核对远端提交；另一人再更新。main 有其他更新时由 Codex 处理整合并重新验证。不是实时同步，也不自动合并冲突或覆盖未提交改动。

## 检查

`npm run doctor` 检查安装/服务和转换工具路径；`npm run setup:native` 补装缺失的转换工具；`npm run check` 执行类型检查与隔离测试；`npm run guard` 检查仓库文件边界。

技术：React + Vite、Node 内置 HTTP 与 SQLite。无云端数据库；自动改稿通过各人本机 Codex CLI 调用其配置的模型服务。所有自动化详细约定见 AGENTS.md。

## Pad 播放操作

轻点图片或 GIF 放大；放大后轻点图片或空白处收起。成组图片在图片区左右滑动切换，也可点至少 44px 高的上一张/下一张按钮。图片手势不会翻整页；在图片区外左右滑动翻页。Pad 上底部播放操作持续可见。离线 HTML 导出使用相同交互。

讲品模板使用品牌蓝、明黄、暖白配色。模板样式更新会影响工作台中所有版本的显示，固定版本保留的是内容快照；需要完全固定外观时，保留当场导出的独立 HTML。

## 一键 Codex 改稿

反馈面板支持自动调用本机 Codex CLI，默认沿用本机配置，也可调整模型和推理强度。完成后预览再应用。[安装与使用说明](docs/Codex自动改稿.md)。
