# 发布演示链接

工作台顶部「发布」会将当前草稿生成为播放网页，通过内网上传网关发布。网页、字体、图片、GIF 和视频作为同一发布目录下的独立对象上传；全部素材上传成功后才会返回链接。打开链接时先加载网页与当前页所需素材，切换到其他页面时会主动加载该页图片和视频；按需加载只改变下载时机，不省略页面内容。较大的静态 PNG 图片在能明显减小时转换为高质量 WebP，动画 PNG、GIF 和离线导出文件保持原样。发布后返回 HTTPS 播放链接。每次使用独立对象键，不覆盖旧链接。同一项目首次成功发布标为 v1.0，之后依次为 v2.0、v3.0；失败的上传不占用编号。项目广场与编辑页显示最新发布版本，发布弹窗可查看全部历史链接。旧记录会从 v1.0 开始编号，原链接保持不变。

首次使用时，在本机 `.local/publish-config.json` 配置：

```json
{
  "gatewayUrl": "https://内网上传网关地址",
  "apiKey": "网关 API Key"
}
```

也可以用本机环境变量 `UPLOAD_GATEWAY_URL` 和 `UPLOAD_API_KEY` 覆盖。配置文件、发布记录、上传内容均留在 `.local/`，不进入 Git。不要把 API Key 写进源代码、前端页面或文稿包。

## 给同事分发公司统一配置

负责人在已配置发布的电脑执行：

```sh
npm run team-config -- export
```

命令会生成 `delivery/company-publish-config.json`，包含网关地址和共用 API Key。这个目录被 Git 忽略。请只通过公司内部受控渠道将文件发给有发布权限的同事；文件一旦外泄，应由网关负责人轮换 API Key。工具不会把密钥放进公开 GitHub 仓库。

同事将收到的文件命名为 `company-publish-config.json`，放在项目根目录，运行 `npm run setup` 或双击安装入口。安装时会导入 `.local/publish-config.json`，并删除根目录临时副本。已有的本机发布配置不会被覆盖。若文件放在其他位置，可以先执行：

```sh
npm run team-config -- import /收到的文件路径/company-publish-config.json
```

以后点击「更新工具」不会删除 `.local/` 中的配置，因此每台电脑只需导入一次。这个流程仍需要将密钥安全地送达每台电脑；如公司后续提供统一身份认证或受保护的配置服务，可再改成自动领取短期凭证。

上传使用网关的 `POST /v1/presign` 和返回的预签名 `PUT` 地址。全部素材上传成功后才上传入口网页；必须由网关返回 `public_url`，工作台才会显示可分享链接。发布记录保存在 `.local/publications.json`；记录只供查找链接，不管理远端文件。网关如设置存储生命周期，界面会显示其提示。旧链接不会随本机草稿的后续修改自动更新。顶部「导出 HTML」仍会把全部素材嵌入一个文件，供离线使用。
